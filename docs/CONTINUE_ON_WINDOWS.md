# Продолжение разработки CLIPALKA на Windows

Состояние проекта на 6 ноября 2026 года. Это краткий контекст для нового чата
Codex; полная переписка, вложения и локальные файлы Mac в этот документ не входят.

## С чего начать

1. Работать с репозиторием https://github.com/psychotic666/CLIPALKA, ветка `main`.
2. Проверить `git status`, сохранить чужие/несохранённые изменения.
3. Прочитать этот файл, `README.md`, `design-system/clipalka/MASTER.md`,
   `native/README.md` и `docs/WINDOWS_TEST_CHECKLIST.md`.
4. Уточнить текущую задачу пользователя. Сам перенос проекта не означает запрос
   на очередной редизайн, изменение захвата или публикацию новой версии.

На Windows проект можно разместить в `C:\Projects\CLIPALKA`. Папка должна быть
клоном Git, чтобы продолжать работу с историей и отправлять изменения в GitHub.
Доступ к GitHub и необходимые инструменты настраиваются на этом компьютере.

## Что это за приложение

CLIPALKA — C# / .NET 8 / WPF, Windows 10/11 x64. Основные функции: обычная запись,
сохранение последних 30 секунд, системный звук и микрофон, выбор монитора,
аудиоустройств, папки и FPS, клавиатурные и контроллерные сочетания, трей,
уведомления, галерея и обновляющий установщик.

Ожидаемое поведение: игра остаётся источником при переключении на Telegram или
другие окна. Когда игра не обнаружена, используется выбранный монитор. Нужно
проверять фактический захват, а не обещать совместимость по одному названию игры.
Клавиатурные хоткеи назначаются нажатием, могут быть отключены; названия клавиш
всегда английские. Пользователю важно сочетание `Shift+Z`.

Звук Discord попадёт в системную дорожку, если проходит через выбранное устройство
вывода. Виртуальные устройства SteelSeries Sonar должны поддерживаться.

## Дизайн

Новое направление, утверждённое пользователем 6 ноября: Signal — угольный фон,
фиолетовый акцент #9566F5, крупная типографика, подчёркнутые вкладки в заголовке,
широкий предпросмотр и плоская полоса действий. Сначала «Сохранить момент», затем
запись и микрофон. Это заменяет прежнее бирюзовое направление Dota2ProTracker.
Не возвращать прежние боковые панели или крупную округлую навигацию.
Точные цвета и структура находятся в `design-system/clipalka/MASTER.md`.
Signal реализован в исходниках отдельно от опубликованного RC3; новый релиз
с этим оформлением пока не публиковался.
Пользователь просил применять `ui-ux-pro-max`, если навык доступен.

Исправлен подтверждённый дефект наведения: фон hover рисовался внутри padding
и выглядел отдельным прямоугольником. Теперь отступ находится у ContentPresenter,
а hover покрывает скруглённый контрол целиком. Не возвращать padding на корень
шаблона, содержащий hover. Основные файлы — `MainWindow.xaml` и `Themes/Studio.xaml`.

Предпросмотр в обычном запуске использует настоящий последний сохранённый клип.
`Assets/studio-demo.png` используется только в `--render-ui`. Не подменять реальные
данные демонстрационными изображениями или фальшивым состоянием захвата.

## Звук и видео: история проблемы

Проверяемая конфигурация: RTX 3060, replay 30 секунд / 120 FPS,
Sonar Gaming + Sonar Microphone. Для микрофона сообщались 2 канала, 24 бит,
48 кГц. Скрип голоса был слышен в клипе при уменьшении громкости в CLIPALKA,
при 100% пользователь его не замечал. Были также жалобы на плавность видео.

В native-микшере подтверждено дополнение коротких блоков микрофона нулями.
Исправление в `native/PcmBlockAligner.h` сохраняет остатки PCM между блоками;
оно уже входит в RC2 и RC3. При изменении только громкости replay не перезапускается,
коэффициенты применяются плавно. Нужен новый реальный Sonar-клип для аппаратной
приёмки. Нельзя считать, что любой новый аудиодефект обязательно имеет ту же причину.

Важно: Windows-сборка должна использовать исправленную ScreenRecorderLib,
а не стандартную DLL из NuGet. Скрипт `native/Build-Recorder.ps1` собирает
зафиксированный upstream с патчем; маркер DLL — `CLIPALKA PCM FIFO 1`.
Подробности, зависимости и команды есть в `native/README.md`.
Кросс-компиляция на Mac не подтверждает работу исправленного движка Windows.

## Геймпады: последние изменения

Нужны DualSense по Bluetooth и Flydigi по Bluetooth; конкретные модели Flydigi
пока неизвестны. В RC2 DualSense позволял назначить и сохранить сочетание,
но нажатие не сохраняло клип. Пользователь подтвердил нажатие «Сохранить настройки».

В RC3:

- `ControllerChordMatcher` реагирует на короткое нажатие без обязательных 400 мс.
  Лишние игровые кнопки разрешены. Для следующего клипа нужно отпустить кнопки
  назначенного сочетания. Зажатые кнопки при старте/подключении не создают клип.
- Применение привязки в `SaveSettingsButton_Click` независимо от клавиатурного
  обработчика. Сбой инициализации клавиатуры не должен блокировать контроллер.
- Новый `ControllerHotkeysOnlyWhileGameActive` отделён от клавиатурного
  `HotkeysOnlyWhileGameActive`; ограничение геймпада по умолчанию выключено.
- В настройках есть текущий ввод и объяснение распознанной, но заблокированной
  команды. Диагностика содержит ограниченную историю событий; не отправлять её
  автоматически куда-либо.
- Добавлен независимый фоновый Raw Input: у реального DualSense Bluetooth
  WinMM видел устройство, но возвращал нейтральное состояние. Сырые отчёты
  `0x31` доходили, однако стандартный HID-парсер Windows отклонял их с
  `0xC011000A`. Теперь полный формат DualSense разбирается отдельно с CRC32.
  Для проверки выбирается «DualSense · Raw Input» и сочетание назначается заново;
  прежние привязки других источников автоматически не переинтерпретируются.
- Источники ввода: Raw Input, WGI, Desktop HID/WinMM и XInput. Разные варианты одного
  устройства могут быть видны отдельно; назначается один источник.
- `ControllerHotkeyVerification` проверяет обучение, сохранённую привязку,
  команду replay, лишние кнопки, отсутствие дублей, блокировку и reconnect.
- Назначение ждёт до 30 секунд; его результат и причина тайм-аута остаются
  видимыми минимум 4 секунды. Неизвестное состояние Raw Input до первого
  настоящего отчёта не считается отпусканием кнопок и не разрешает ложный клип.
- `--verify-input <папка>` теперь перечисляет реальные источники всех API.
  `--probe-controller <папка>` три минуты пишет изменения кнопок и состояние
  чтения в `input-reports.txt` без записи видео/звука и без отправки в сеть.

Пользователь 6 ноября подтвердил сохранение настоящего клипа с DualSense
Bluetooth через Raw Input. Flydigi не проверен.

В среде CI физического Bluetooth-контроллера нет. Проверка RC3 настоящим DualSense
и Flydigi остаётся необходимой. Для нового сбоя сначала посмотреть текущий ввод,
статус, выбранный источник и состояние replay, затем воспроизвести причину.

## Сборка и релизы

На главной добавлен живой индикатор микрофона вместо переключателя-ползунка;
сама кнопка по-прежнему включает/выключает микрофон. NAudio.Wasapi 2.2.1 держит
отдельный shared capture-клиент только при видимой главной и читает пик выбранного
endpoint с применённой громкостью CLIPALKA. Звук не воспроизводится и не сохраняется.
Mute, скрытие окна и переход в настройки освобождают клиент; недоступный вход
показывает пустой индикатор с пояснением. `--verify-microphone-meter <папка>`
проверяет выбранный реальный вход, mute, suspend/resume и недоступный endpoint.
Нулевой пик при тишине не подтверждает реакцию на физическую речь.

В «Настройки → Видео и файлы» добавлен переключатель запуска вместе с Windows.
Он применяется только общей кнопкой сохранения, использует HKCU Run (без прав
администратора), а его состояние читается непосредственно из Windows. Отдельного
дублирующего флага в JSON нет. Автозапуск сам по себе не включается. Установщик
обновляет существующую запись, удаление убирает её только для своей копии.
`--verify-startup <папка>` проверяет операции в изолированной тестовой ветке HKCU,
не меняя настоящий автозапуск. При ручном переносе portable-папки автозапуск
нужно заново сохранить из приложения по новому пути.

Для Windows нужны Git, .NET 8 SDK, Visual Studio 2022 Desktop C++, ATL,
C++/CLI v143, Windows SDK и targeting pack .NET Framework 4.8. Сначала проверить
установленные инструменты. Native DLL собирается перед приложением по инструкции
`native/README.md`. Не отключать обязательную проверку исправленного recorder.

Workflow `.github/workflows/build.yml` выполняет Windows-проверки. Тег `v*`
собирает Setup и portable ZIP, вычисляет SHA-256 и создаёт черновик релиза.
Публиковать релиз только по явному запросу пользователя и после проверки файлов.
Для следующих веток использовать префикс `codex/`, когда отдельная ветка нужна.

Установщик сохраняет прежнюю папку и AppId, не создаёт вторую установку,
сохраняет клипы и настройки. Очистка удаляет только неизменённые устаревшие
файлы из инвентаря. Не удалять неизвестные файлы или записи пользователя.

## Что не переносится одним клонированием

Вложения старого чата, временные видео/скриншоты, ignored-папки `artifacts/`
и `publish/`, установленные SDK, локальные навыки и авторизации не находятся
в Git. При необходимости исходных клипов пользователь прикрепит их снова.
Новый чат должен прочитать этот документ; он не получит полную старую переписку
автоматически из репозитория.
